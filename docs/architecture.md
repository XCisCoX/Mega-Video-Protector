# Mega Vault Protect architecture

## Phase boundary

Phase 1 established the build, module boundaries, dependency findings, and security design. Phase 2 pinned the production dependencies and implemented the secure vault core and the setup/login UI shell. Phase 3 implemented encrypted import, the chunked package format, and the gallery. Phase 4 implemented vault administration: video removal and password change. Phase 5 implemented the streaming authenticated package reader, FFmpeg media probing, and encrypted thumbnails. Phase 6 added import-time thumbnails, thumbnail re-keying on password change, Explorer-style gallery views, and in-memory video playback. Phase 7 added multi-tag organization with tag filtering and converted the unlocked view into a full Windows Explorer-style layout. The project deliberately never substituted plain SQLite for SQLCipher or a fake vault for the real one.

## Phase 2 implementation status (verified by `VideoVaultCore.Smoke`)

- **Key derivation.** Argon2id runs through the pinned `argon2` port (`argon2id_hash_raw`) with safety bounds (memory 8 MiB–1 GiB, iterations 1–20, parallelism 1–16, password ≤ 4096 bytes). This is a deviation from the Phase 1 design note that suggested libsodium's `crypto_pwhash` wrapper; both are Argon2id and the direct port was chosen during pinning.
- **Subkeys.** Domain-separated 32-byte subkeys via libsodium `crypto_kdf`: database subkey id 1 (context `MVPDB001`), password-verifier subkey id 2 (context `MVPVEr01`).
- **Password verifier.** A random 16-byte value is sealed with XChaCha20-Poly1305 under the verifier subkey (random nonce). The 24-byte nonce and 48-byte ciphertext live in `vault.meta`. Open requires the verifier to authenticate; if the verifier rejects but the SQLCipher key still opens the database, the error is `AuthenticationFailed` (metadata damage) rather than `WrongPassword`.
- **Vault layout.** `vault.meta` (64-byte header + nonce + ciphertext), `vault.db` (SQLCipher), `vault.ready` (written last), `vault-data/`, and `.tmp/` staging. `Vault::exists` requires metadata, database, and ready marker.
- **Crash-consistent creation.** Build `vault.db` in `.tmp`, close and flush, atomically rename into place, atomically write `vault.meta`, then write `vault.ready`. Any failure removes all creation artifacts, so a partial vault cannot masquerade as complete.
- **SQLCipher connection.** Direct C API with RAII statements and transactions. Per-connection hardening: 4096-byte pages, HMAC-SHA512, PBKDF2-HMAC-SHA512 at 256000 iterations, `cipher_memory_security ON`, `secure_delete ON`, `foreign_keys ON`, 5 s busy timeout, extended result codes. The `SQLITE_HAS_CODEC` definition is applied to the core target so the header exposes `sqlite3_key`.
- **Schema.** `schema_migrations(version, applied_at)` and `vault_metadata(singleton, format_version, external_metadata, verifier_nonce, verifier_ciphertext, created_at)` created in a `BEGIN IMMEDIATE` transaction; `verify_vault_metadata` cross-checks the database row against the external metadata file after open.
- **Sensitive memory.** `SensitiveBuffer` uses `sodium_malloc`/`sodium_mlock`, wipes with `sodium_memzero`, and is non-copyable. Wiping remains best effort.
- **UI shell.** Setup, login, and unlocked pages consume only public core APIs. Core operations run via `QtConcurrent`; the UI thread does no crypto or database work. A 5-minute activity-based auto-lock and `QSettings`-remembered vault location are included. Qt SQL is not linked.
- **Known limitations.** No media import/gallery/playback yet; password policy is non-empty ≤ 4096 bytes; auto-lock is in-app activity based; Release build and crash-injection tests outstanding.

## Phase 3 implementation status (verified by `VideoVaultCore.Gallery`)

- **Package format implemented as designed.** `vault-data/<h0h1>/<h2h3>/<sha256-of-ciphertext>.vvp` holds an authenticated 68-byte canonical header (`MVPVVP01` magic, format version 1, algorithm 1 = XChaCha20-Poly1305 chunked, chunk size, plaintext size, chunk count, 16-byte package id, 16-byte nonce prefix), a 16-byte header AEAD tag, then one independently authenticated ciphertext per chunk. Chunk nonce = nonce prefix || 64-bit chunk index; the header uses the reserved all-ones index. Chunk AD binds header SHA-256 digest, package id, chunk index, plaintext length, and the final-chunk flag. Chunk size is validated to 1..16 MiB on read; the importer uses 64 KiB.
- **Import flow.** `Vault::import_file` streams the source into `vault-data/.tmp/import_*.vvp`, hashes the complete ciphertext incrementally (SHA-256), flushes with write-through, atomically renames into the hash-derived path, then commits the `videos` row and the wrapped file key in a single `BEGIN IMMEDIATE` transaction. Any failure removes the staged or renamed package, so a committed row cannot point at a partial package. Each import draws a fresh random 256-bit file key and package id: identical source content imports as a distinct package (the design hashes ciphertext; content deduplication is intentionally absent).
- **Key wrapping.** File keys are sealed with XChaCha20-Poly1305 under the wrapping subkey (id 3, context `MVPRAP01`), with the package id as associated data, into a random nonce. Only the 48-byte wrapped key and nonce are stored in `video_keys`; unwrapping happens per read under the wrapping subkey, and the transient plaintext key copy is wiped best-effort.
- **Schema migration v2.** `videos` (id, display_name, original_size, package_relative_path UNIQUE, package_size, package_sha256, format_version, algorithm_id, chunk_size, package_id, imported_at) and `video_keys` (video_id PK → videos ON DELETE CASCADE, wrapped_key, wrap_nonce). Migration runs in its own transaction on both create and open of existing Phase 2 vaults, tracked by `schema_migrations`.
- **Read and integrity.** `Vault::read_video_bytes` verifies the file size against the header, the header tag, and every chunk tag before returning plaintext (`PackageModified` on any mismatch, `PackageMissing` if the file is gone, `UnsupportedPackageVersion` for a newer format). `Vault::package_path` resolves and existence-checks a package. `Vault::list_videos` returns the gallery ordered by import time.
- **Threading.** A per-vault `std::mutex` held by `unique_ptr` (stable address across `Vault` moves) serializes `lock()`, `is_unlocked()`, `kdf_parameters()`, and all gallery/import operations. Worker threads hold a `shared_ptr` to the vault; the owner may `lock()` concurrently and the workers observe either the completed operation or a locked error. The Qt shell runs import and listing on `QtConcurrent` threads and performs no crypto or database work on the UI thread.
- **Known limitations.** No thumbnails/probing/playback (FFmpeg in Phase 5); `read_video_bytes` is whole-file-in-memory (verification/export only; playback gets a bounded streaming reader); import has no cancellation/progress callback; Release build and crash-injection tests outstanding.

## Phase 4 implementation status (verified by `VideoVaultCore.Admin`)

- **Video removal.** `Vault::remove_video` queries the row, deletes it in a transaction (the wrapped key cascades through `video_keys.video_id → videos.id ON DELETE CASCADE`), then removes the package file. The row is committed before the file is deleted, so a committed row never points at a removed package; a failed file removal leaves a replaceable orphan. Unknown ids return `InvalidArgument`; locked vaults return `InvalidArgument`.
- **Password change.** `Vault::change_password` first proves knowledge of the current password: it re-derives the master key from the on-disk metadata salt/parameters and compares it in constant time with the live master key, returning `WrongPassword` without touching any state. On success it: derives a fresh hierarchy (new random salt, new Argon2id parameters, new database/verifier/wrapping subkeys), re-wraps every file key under the new wrapping subkey (same package-id AD), builds new metadata that keeps the vault id (ready marker stays valid) with a freshly sealed verifier, writes the new `vault.meta` atomically, updates the `vault_metadata` record and all `video_keys` rows, re-encrypts the database with `sqlite3_rekey`, and swaps the session's master key and parameters. Large packages are never re-encrypted; only wrapped keys change.
- **Ordering and crash window.** The external metadata is published before the database record/keys are updated, and the SQLCipher rekey is last. A crash between these steps can leave the vault in a state where neither password cleanly unlocks it (all data remains intact). Recovery tooling and crash-injection tests are outstanding; the happy path, wrong-current rejection, and chained changes are verified.
- **UI shell.** The unlocked page adds "Remove selected" (uses the gallery selection's video id) and "Change password…" (modal dialog with current/new/confirm and the Argon2id profile). Both run on `QtConcurrent` workers against the shared vault, like import and listing.

## Phase 5 implementation status (verified by `VideoVaultCore.Reader` and `VideoVaultCore.Media`)

- **Streaming authenticated reader.** `internal::PackageReader` (in `core/src/package.cpp`) opens a package with the unwrapped file key, verifies the canonical header and its tag once, and then serves plaintext on demand: `seek(offset)` clamps to EOF (FFmpeg probes may seek past the end) and `read(destination)` loops across chunk boundaries until the buffer is full or EOF. A bounded LRU cache (4 slots) keeps recently decrypted 64 KiB chunks; every chunk is re-authenticated before its plaintext is exposed (`PackageModified` on tamper). A subtle early bug — empty default cache slots matched chunk index 0, making `read()` spin forever — was caught by the Reader test's hang and fixed by initializing slot indices to `UINT32_MAX`. `Vault::read_video_range(video_id, offset, size)` exposes the reader through the public API (fewer bytes at EOF, empty at/past the end), and `read_video_bytes` now delegates to it; the old whole-file decryption path is gone.
- **FFmpeg integration.** The core links the vcpkg FFmpeg 7.1.1 shared libs (`avcodec`, `avformat`, `avutil`, `swscale`). The FFmpeg install root, like the build trees, lives outside the project (space-in-path breaks MSVC response files — LNK1181 on `-libpath`). Two further Windows quirks are documented and handled: the port installs stub `.lib` import libraries with no symbol entries, so `scripts/regenerate-ffmpeg-importlibs.sh` rebuilds them from the DLL export tables (`dumpbin /exports` -> `.def` -> `lib.exe /def`); and FFmpeg 7.x public headers carry no `extern "C"` guards, so every FFmpeg include is wrapped in `extern "C" { ... }` (without it, C++ references are mangled and cannot match the DLLs' undecorated exports).
- **Probing and thumbnails (`core/src/media.cpp`).** A custom AVIO context layers over `PackageReader` (read/seek callbacks; `AVSEEK_SIZE` supported), so `avformat_open_input` reads straight from the encrypted package — plaintext never touches disk. `internal::probe_media` returns duration (ms), width/height, rotation (from `AV_PKT_DATA_DISPLAYMATRIX` side data), and the codec name. Thumbnail extraction seeks to ~10% of the stream (capped at 10 s), decodes one frame, scales to fit the requested `max_dimension` (aspect-preserving, no upscaling), and encodes JPEG (yuv420p with full-range color). A lifetime bug — the AVIO context died before the `AVFormatContext` referencing it — was fixed by owning both in a `FormatHandle` whose destruction order frees the format first.
- **Thumbnail storage.** Schema version 3 adds `thumbnails(video_id PK → videos ON DELETE CASCADE, mime, width, height, nonce, ciphertext, created_at)`. The JPEG is encrypted under the thumbnail subkey (id 4, context `MVPTMB01`) with `video_id || package_id` as AEAD associated data (design note 5 "Thumbnails are encrypted before storage" is now implemented). `Vault::generate_thumbnail` decodes/stores/returns; `Vault::thumbnail` decrypts and returns; thumbnails persist across reopen and cascade away with `remove_video`.
- **Test fixture.** `VideoVaultCoreMediaTests` builds its input at runtime with the FFmpeg libraries: MJPEG codec (yuv420p, full range) in a Matroska container, 64x64, 10 fps, 20 frames. Rawvideo was rejected by the AVI muxer and produced bogus durations in Matroska/NUT; MJPEG gives proper duration signaling. Two fixture bugs surfaced along the way: `sws_scale` needs the *row* stride (width × bytes-per-pixel), not the frame stride (out-of-bounds reads segfaulted); and packet pts/dts must be rescaled to the muxer's real `time_base` (Matroska uses 1/1000) or the muxed duration collapses to ~20 ms.
- **UI shell.** The gallery attaches stored thumbnails as 96 px icons asynchronously and adds a "Generate thumbnail" button for the selected video; both run through `QtConcurrent` against the shared vault (build-verified; UI behavior is user-tested).

## Phase 6 implementation status (verified by `VideoVault.Playback`)

- **Import-time thumbnails.** `Vault::import_file` calls the lock-free `generate_thumbnail_locked` helper right after the database commit (best effort; non-video or undecodable content fails quietly and never fails the import). The public `generate_thumbnail` remains for regeneration. The media test asserts a thumbnail exists immediately after import.
- **Thumbnail re-keying.** Password changes derive new subkeys from the new master key, so stored thumbnails (encrypted under the old thumbnail subkey) would become unreadable. `change_password` now derives the old and new thumbnail subkeys up front and, after the rekey, decrypts every stored thumbnail (AD: `video_id || package_id`), re-encrypts it under the new subkey with a fresh nonce, and stores it back. Per-row failures drop that thumbnail rather than failing the change. The media test asserts byte-for-byte thumbnail equality across a password change and reopen.
- **Explorer-style gallery.** The unlocked page has a view switcher (Details / Large icons / List). Details uses a `QTreeWidget` with Name, Size, Duration, Resolution, Codec, and Imported columns (duration/resolution/codec filled asynchronously via `media_info`); icon modes use a `QListWidget` in `IconMode`/`ListMode` with 128 px or 32 px thumbnails. Both views carry the video id in item data, share a `selectedVideoId()` helper for the admin buttons, and open the player on double-click.
- **In-memory player.** `MediaDecoder` (`qt-app`, GUI-free) streams the plaintext of an encrypted video through `Vault::read_video_range` with a custom AVIO context — the same pattern as the Phase 5 probe — decodes video frames (sws → BGRA `QImage`) and audio (swresample → s16le), supports `seek_to` with decoder flush, and exposes a PCM pull buffer. `PlayerWindow` paces frame display against the audio clock (`QAudioOutput::processedUSecs`, wall clock when silent), feeds decoded PCM to a `QAudioOutput` through a pull-mode `AudioSink` QIODevice, and provides play/pause plus a seek slider. Nothing is written to disk; no whole-file plaintext buffer is materialized. The headless `VideoVault.Playback` test imports an MJPEG+PCM fixture and verifies duration, resolution, ≥10 decoded frames, a valid first frame, post-seek decoding, and non-empty audio samples.
- **Playback path decision.** Qt 5.12's WMF multimedia backend was not used with a custom `QIODevice` (its device support is unreliable for the container/codec variety this vault stores); the in-process FFmpeg custom-AVIO decode path — the design's documented fallback — became the primary player. The `QtVaultIODevice`/WMF route remains a possible future optimization, not a requirement.

## Phase 7 implementation status (verified by `VideoVaultCore.Tags`)

- **Tag schema (v4).** `tags(id, name UNIQUE COLLATE NOCASE, created_at)` and `video_tags(video_id → videos ON DELETE CASCADE, tag_id → tags ON DELETE CASCADE, created_at, PK(video_id, tag_id))`, migrated in a transaction on create and open. Tag names are stored as entered; uniqueness and lookups are case-insensitive.
- **Core API.** `Vault::add_tag` normalizes (trim, reject empty/>64 bytes/control chars → `InvalidArgument`), `ensure_tag` creates the tag with `INSERT OR IGNORE` and resolves its id, and `tag_video` associates idempotently (`INSERT OR IGNORE`) after verifying the video exists. `remove_tag` deletes the association; `tags_for_video` and `list_tags` (LEFT JOIN with `count(video_tags.video_id)` for per-tag counts) return sorted results. `Database::list_videos` loads each row's tag names, and `VideoInfo` exposes them, so gallery rendering and client-side filtering need no N+1 queries in the UI.
- **Explorer-style unlocked view.** The unlocked page is now full-bleed: a slim command bar (view-mode combo, tag-filter combo, Import video…, Change password…, small flat Lock button), the gallery filling the window (7-column Details tree with a Tags column, or icon/list modes), and a status bar (vault path, "N videos · X MB", inline messages). The centered card layout is gone; the view mode persists via `QSettings`.
- **Tag UX.** A toolbar search box (plus the tag-count dropdown) filters both views live by tag substring or video name, combined with the dropdown when both are active. The tag editor dialog (checkbox list of all tags + new-tag input) loads its data on a worker thread, diffs checked vs applied names on OK, and applies add/remove through `QtConcurrent`; the filter and gallery refresh afterwards.
- **Dark-theme and icon fixes.** The global stylesheet now styles `#gallery` tree/list items, the header view, scrollbars, and sliders explicitly (the QTreeWidget previously fell back to the light palette and rendered white-on-dark). Icon-mode clipping was fixed by dropping `setUniformItemSizes` (incompatible with wrapped text), enlarging the grid (icon 128 + text ≈ 192 px), per-pixel scrolling, and relayout-from-top on view switches.
- **Upgraded player.** `PlayerWindow` gained a bottom control bar (seek slider with live time, volume slider + mute persisted in `QSettings`, fullscreen button), fullscreen via button/double-click/F with auto-hiding controls (2.5 s idle while playing) and blank cursor, Esc to exit, and keyboard shortcuts (Space — replaying from the start at EOF — Left/Right ±5 s, Up/Down volume). Seek correctness was fixed with an offset-based audio clock (`audioClockOffsetMs_ + processedUSecs`), because `QAudioOutput::reset()` zeroes `processedUSecs` and the old code collapsed the playhead to 0 after any seek; seeks now restart the device with `stop()`+`start()`, decode and show the first frame at the target immediately, and stay paused when the user seeks while paused.
- **A/V sync fixes.** (1) Silent start: `QAudioOutput` goes to `IdleState` and stops pulling once a read returns 0 bytes — with an empty sink at startup the sound stayed dead until an explicit resume. Fixed by prefilling the sink with ~200 ms of decoded audio before `start()` and by `feedAudio()` restarting the device whenever it idles/stopped again. (2) A/V desync: the tick loop decoded one frame per 16 ms tick unconditionally, so video advanced by a whole frame each tick (2–6x real speed for low-fps content) while audio advanced in real time. Video now decodes only while `lastPtsMs_` is behind the playhead, and `current_playhead_ms()` trusts the audio clock only in `ActiveState` (wall clock otherwise), keeping A/V locked; the device buffer is ~125 ms for tight sync.
- **Streaming buffer (selectable memory budget).** `MediaDecoder`'s `VaultSource` now wraps `Vault::read_video_range` in a `StreamCache` read-ahead window: 1 MiB-aligned, sized by a user-selectable budget (4–128 MiB, default 32, persisted in `QSettings` via the player's "Cache" combo), refilled with one big range read at a low-water mark and re-anchored on seeks. All AVIO reads are memcpy from RAM after the window loads. This replaces the previous behavior where every AVIO read (often 4 KB) opened a fresh `PackageReader` (DB query + key unwrap + file open) and decrypted its chunks — the root cause of the "streaming is slow" reports. The AVIO buffer was raised to 128 KB so the demuxer crosses the callback less often. The playback test verifies the budget setter and decoding through the cache.
- **Worker-thread decode pipeline.** `PlayerWindow` moved decoding off the UI thread onto a dedicated worker (`std::thread` + atomics; no QThread machinery). The worker streams through `MediaDecoder` — cache refills and `sws`/scaling stalls now block only the worker — publishes each frame into a mutex-guarded slot, and appends PCM straight into the thread-safe `AudioSink` (with ~1 s backpressure cap during catch-up). The UI timer only paints the latest frame, updates the seek bar, and owns `QAudioOutput` (created once the worker reports the audio format; the idle-wake pattern for `QAudioOutput` moved to the UI tick). Pacing: the worker computes the playhead from a monotonic `QElapsedTimer` anchored at start/seek/pause-resume, and re-syncs to the UI-published audio clock only when the two drift >250 ms — decode speed and surface size can no longer influence playback rate. This fixes the freeze pattern (UI thread never blocks on I/O) and the "smaller window = faster video" bug (the old code paced against `processedUSecs`, which jumped whenever a fast tick dumped audio into the device).
- **Performance pass (one-scale decode + direct paint).** (1) `MediaDecoder::set_display_size` makes sws convert straight from the coded frame to the display size (scaler rebuilt only on resize), eliminating the second per-frame QImage scale. (2) The QLabel+QPixmap surface was replaced by a `VideoSurface` widget that paints the already-display-sized frame via `QPainter::drawImage` (aspect-fit on black) — no `QPixmap::fromImage` 8 MB deep copy per frame. (3) Pacing no longer reads `processedUSecs` at all: the worker holds video only while the audio sink holds >0.8 s of samples (device draining slower than real time), which keeps A/V locked without coupling playback rate to UI thread load or device-clock flakiness. Together these fix the "1080p at 4–10 fps, fewer frames than the video" report: at the default window size the video is decoded at window resolution (one scale), fullscreen needs no scaling, and the UI thread's paint cost is a straight blit.
- **Seek fixes.** The UI tick used to overwrite the slider value every 16 ms, so dragging the thumb fought the tick and scrubbing snapped back; a `seeking_` flag now freezes tick updates during a drag, with a live time preview. A manual seek also clears the `ended_` state — after EOF the tick kept forcing the slider to the maximum and pressing Play issued `requestSeek(0)`, i.e. the observed "can't jump to the middle, it starts over" behavior. The playback test now asserts the first post-seek frame is within 50 ms of the target.
- **Seek lands where you drag.** (1) `MediaDecoder::open` now feeds the AVIO size callback the PLAINTEXT size (`VideoInfo.original_size`), not the encrypted `.vvp` file size — the package is larger (header + per-chunk AEAD), and the wrong size skewed `SEEK_END`/`AVSEEK_SIZE` and the `StreamCache` EOF clamping. (2) The worker's seek branch decodes-and-skips from the keyframe the demuxer landed on to within 250 ms of the requested target before publishing a frame (bounded at 120 frames, gap audio discarded): with sparse keyframes, the old behavior showed a frame seconds earlier and read as "the video won't move forward/backward". (3) `seek_to` tries `av_seek_frame(..., AVSEEK_FLAG_BACKWARD)` first with `avformat_seek_file` as fallback, returns false only when both fail, and the worker keeps the old position (with a qWarning) instead of silently continuing.
- **GitHub Release workflow.** `.github/workflows/release.yml` builds Release on `windows-latest` (fresh vcpkg for the pinned baseline, Qt 5.12.12 via `install-qt-action`, MSVC dev environment, parameterized import-lib regeneration, preset overridden for CI paths), runs all 7 suites, and publishes a zip (exe + Qt runtime + FFmpeg DLLs) via `softprops/action-gh-release` on either a manual `workflow_dispatch` (optional version input; creates the tag) or a `v*` tag push. `scripts/regenerate-ffmpeg-importlibs.sh` now reads `VCToolsInstallDir`/`MVP_*` env overrides for CI while keeping the local defaults.

## Components

- `VideoVaultCore`: C++20 static library with no Qt dependency. It will own vault lifecycle, key management, SQLCipher access, package I/O, import jobs, integrity checks, and decrypted random-access readers.
- `VideoVaultApp`: Qt 5.12.12 desktop UI. It depends on the core through standard C++ interfaces. A narrow adapter will translate core events/results to Qt signals, models, and `QIODevice`.
- `VideoVaultCoreTests`: focused native tests. Crypto and crash-consistency cases will be added with each implementation phase rather than as placeholders.

Public core headers will expose value types, opaque handles, RAII objects, cancellation tokens, callbacks, and typed `Result<T, Error>`-style outcomes. No libsodium, SQLCipher, FFmpeg, SQLite, or Qt type will cross the public core ABI.

## Threading and ownership

The UI thread performs no encryption, hashing, probing, or database I/O. Core jobs run on owned worker threads with cooperative cancellation and progress callbacks. SQLCipher connections are not shared concurrently; a bounded connection strategy gives each worker exclusive connection ownership. Transactions establish the database/package consistency boundary.

Sensitive buffers are non-copyable RAII objects backed by libsodium guarded/locked memory where available and wiped on release. OS paging and compiler/runtime copies mean wiping remains best effort and will be documented as such.

## Cryptographic design

No custom primitive is introduced.

1. Argon2id (pinned `argon2` port, `argon2id_hash_raw`) derives a 256-bit root master key from the password and a random 16-byte salt. Memory, operations, and parallelism/security-profile metadata are versioned. The password is not retained.
2. Domain-separated subkeys are derived from the root for SQLCipher, file-key wrapping, and password verification. Reusing one raw key across protocols is forbidden.
3. A dedicated random verifier value is authenticated/encrypted under the verifier subkey. Unlock requires both SQLCipher access and successful verifier authentication.
4. Every video receives an independent random 256-bit file key. File keys are wrapped with XChaCha20-Poly1305 using unique random nonces and authenticated context. Only wrapped keys are persisted.
5. Thumbnails are encrypted before storage in the SQLCipher database.

Password changes derive a new root with a new salt, unwrap and re-wrap only file keys, rekey SQLCipher, and replace the verifier. Large video packages are not re-encrypted. Implemented in Phase 4 (see the Phase 4 status section; the "recoverable transaction protocol" is currently best-effort with a documented crash window).

## Versioned package format (design baseline)

Implemented in Phase 3 (`internal/package.hpp`, `core/src/package.cpp`); see the Phase 3 status section for the exact on-disk layout and verified behavior.

The first format uses libsodium XChaCha20-Poly1305 AEAD in independently authenticated fixed-size chunks rather than `secretstream`. `secretstream` is excellent for sequential data but its chained state prevents efficient random seeking; independently authenticated chunks satisfy secure seekable playback.

The authenticated fixed header contains magic, format version, algorithm identifier, header size, chunk size, plaintext size, chunk count, a random package identifier, and a random nonce prefix. Each 24-byte nonce is constructed from a per-package random 16-byte prefix plus the 64-bit chunk index. Since every package also has a unique random file key, `(key, nonce)` reuse is prevented. Chunk associated data binds the canonical header digest, package identifier, chunk index, plaintext length, and final-chunk flag. Each chunk has its own Poly1305 tag, which is verified before plaintext is returned.

Imports write to a vault-local temporary file, flush and close it, hash the complete ciphertext package with SHA-256, verify it, atomically rename it to `<h0h1>/<h2h3>/<64-lowercase-hex>.vvp`, then commit the database row. Cancellation or crashes cannot leave a committed row pointing at a partial package. Package hashes aid lookup and scans; AEAD tags provide modification security.

## Database

The core links directly to SQLCipher's C API and uses RAII connection/statement/transaction wrappers plus prepared statements. Qt's installed `QSQLITE` plugin is plain SQLite and is not an acceptable vault database. Schema migrations run under transactions and track a monotonic schema version. Phase 2 created `schema_migrations` and `vault_metadata`; Phase 3 added `videos` and `video_keys`; Phase 5 added `thumbnails`; Phase 7 added `tags` and `video_tags`. The `import_jobs`, `package_integrity`, and `settings` tables are planned with later phases.

## Media and playback

FFmpeg libraries inspect containers, read metadata, decode a representative frame, handle rotation, and encode JPEG through in-process APIs — all implemented in Phase 5, streaming over the encrypted package through a custom AVIO context (`core/src/media.cpp`). Extensions are only discovery hints.

Playback is implemented in Phase 6 as the in-process FFmpeg custom-AVIO decode path (`qt-app/src/media_decoder.cpp` + `player_window.cpp`): `MediaDecoder` streams plaintext via `Vault::read_video_range` (bounded authenticated chunks), decodes video and audio, and the window renders frames and feeds a `QAudioOutput` in pull mode. The design's original `QtVaultIODevice` -> WMF route was evaluated and deliberately not used (unreliable custom-device support in Qt 5.12's Windows backend). Full plaintext files are never written to normal temporary storage.

## Dependency policy

Use one pinned x64 dependency set compiled with the MSVC ABI. Prefer libsodium for Argon2id, random generation, XChaCha20-Poly1305, hashing, secure memory, and key derivation. SQLCipher brings its required crypto backend; this is a database implementation dependency, not a second application-level crypto design. FFmpeg is media-only. Dependencies will be checked for architecture and build configuration before Phase 2.
